RANDOMCOIN BOT — УЗГОДЖЕНЕ ТЕХНІЧНЕ ЗАВДАННЯ
Версія документа: 03.09.2026

1. ПРИЗНАЧЕННЯ
RandomCoin Bot — окремий Telegram-бот для проведення розіграшів.
Він не повинен бути пов'язаний із логікою основного аукціонного NumizmatCoin_bot.

2. ДОСТУП І БЕЗПЕКА
- Створювати, запускати, завершувати розіграші та керувати ними може тільки власник, визначений через ADMIN_TELEGRAM_ID.
- Інші користувачі можуть лише переглядати активні розіграші та брати участь.
- У Telegram-групах бот не відповідає на звичайні повідомлення, команди чи згадки, щоб не створювати спам.
- RandomCoin Bot потрібно додати адміністратором до ресурсів, де він має публікувати або перевіряти підписку.

3. ГОЛОВНЕ МЕНЮ
Для адміністратора:
- 🎁 Створити розіграш
- 📋 Активні розіграші
- 🏆 Завершені
- ℹ️ Допомога

Для звичайного користувача:
- 🎁 Активні розіграші
- ℹ️ Допомога

У приватному чаті повинні бути:
- Telegram command menu;
- постійна нижня клавіатура.

5. СТВОРЕННЯ РОЗІГРАШУ
Покроковий майстер:
1) назва;
2) опис;

4) від 1 до 15 переможців;
5) буст: немає, ×2 або ×3;
6) завершення:
   - за датою і часом;
   - за кількістю учасників;
7) попередній перегляд;
8) кнопки:
   - ✅ Запустити
   - 🔄 Створити заново
   - ❌ Скасувати

6. ФОТО
- Один розіграш приймає від 1 до 10 фото.
- Бот не надсилає окреме підтвердження після кожного фото.
- Користувач може завантажити фото альбомом або кількома повідомленнями.
- Після завантаження всіх фото натискається одна кнопка «✅ Фото завантажені».
- У попередньому перегляді всі фото показуються разом.
- У групі 2–10 фото публікуються Telegram-альбомом.

7. ПУБЛІКАЦІЯ
- Після «✅ Запустити» розіграш записується в PostgreSQL.
- Розіграш реально публікується в Telegram-групу «Східний Аукціон⚖️».
- Поточний ID групи: -1003918292894.
- У групі публікуються всі фото, текст умов і кнопка «🎁 Взяти участь».
- Кнопка веде користувача в приватний чат RandomCoin Bot через deep-link.
- У самій групі бот на звичайні повідомлення не реагує.

8. УЧАСТЬ
- Один Telegram user_id може зареєструватися в одному розіграші тільки один раз.
- Учасники зберігаються в PostgreSQL.
- Повторне натискання не створює дубль.
- Після успішної реєстрації бот показує підтвердження та поточну кількість учасників.

11. БУСТ
- Для розіграшу адміністратор може увімкнути ×2 або ×3.
- Буст не видається учасником самому собі.
- Адміністратор переглядає список учасників через /participants GIVEAWAY_ID.
- Буст надається командою /boost GIVEAWAY_ID USER_ID.
- У базі базова вага учасника = 1.
- Після бусту вага стає 2 або 3.
- Під час жеребкування вага впливає на шанс, але один користувач все одно може бути обраний переможцем максимум один раз.

12. ЗАВЕРШЕННЯ
Режими:
A) за датою і часом у часовому поясі Europe/Kyiv;
B) автоматично після досягнення заданої кількості учасників.

Також адміністратор може завершити активний розіграш вручну.

ВАЖЛИВО ДЛЯ FREE RENDER:
Якщо безкоштовний Web Service заснув, завершення точно в задану секунду не гарантується.
Код перевіряє дедлайни у фоновому циклі, коли сервіс працює.
Для гарантованого завершення точно за часом пізніше потрібен Render Cron Job або платний always-on Web Service.

13. ВИБІР ПЕРЕМОЖЦІВ
- Кількість переможців: від 1 до 15.
- Використовується криптографічно стійкий генератор Python secrets.
- Переможці унікальні.
- Буст враховується як додаткова вага.
- Один користувач не може виграти два місця в одному розіграші.

15. POSTGRESQL
Таблиці мають окремі назви randomcoin_* і не конфліктують із таблицями аукціонного бота.
Зберігаються:
- розіграші;
- фото Telegram file_id;
- статус;
- спосіб і момент завершення;
- кількість переможців;
- учасники;
- буст/вага;
- список переможців.

20. ЩО БУЛО ПРИЧИНОЮ ПОПЕРЕДНЬОЇ ПЛУТАНИНИ
Найімовірніше проблема була НЕ у зв'язку GitHub ↔ Render.
Спостерігалися конкретні проблеми:
- у репозиторії одночасно з'являлися app.py і app (1).py;
- Render запускає gunicorn app:app, тобто саме app.py, а не app (1).py;
- requirements.txt іноді залишався зі старим psycopg[binary]==3.2.9;
- Render використовував Python 3.14.3, для якого psycopg-binary 3.2.9 не знаходився;
- були коміти без фактичних змін;
- коли новий deploy падав, Render залишав попередню успішну версію Live, тому бот продовжував відповідати старим кодом.

Для стабілізації:
- використовується psycopg[binary]==3.3.5;
- додається .python-version із Python 3.13;
- у репозиторії не повинно бути файлів-дублікатів;
- app.py має власний APP_VERSION для однозначної перевірки.
